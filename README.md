# APICanary

APICanary is an open-source API monitoring application. It schedules HTTP
checks, records response times and failures, tracks downtime incidents, and
sends threshold-based email alerts.

## Current features

- Account signup and login with bearer-token API compatibility and HttpOnly
  browser sessions
- HTTP and HTTPS monitors using GET, POST, PUT, PATCH, DELETE, HEAD, or OPTIONS
- Configurable expected status and check interval
- Encrypted sensitive request headers with redacted API responses
- Automatic scheduling plus manual tests and pause/resume controls
- Latest status, uptime, response-time charts, paginated check history, and
  incident history
- Durable threshold-based email failure and recovery alerts with delivery
  history, test sends, retry backoff, and pending-message recovery
- SSRF protection for localhost, private, link-local, reserved, and otherwise
  non-public destinations
- Owner-scoped monitor, alert, check, and incident APIs

## Roadmap

These features are planned but are not implemented yet:

- Slack and Telegram notifications
- Team workspaces and invitations
- Public status pages
- Configurable history retention and SLA reporting
- Additional alert channels and escalation policies

## Technology

- Next.js 16, React 19, TypeScript, and Tailwind CSS 4
- FastAPI, SQLAlchemy, Alembic, and PostgreSQL
- Celery and Redis for scheduled monitoring
- Vitest and Testing Library for frontend tests
- Python `unittest` for backend tests
- Playwright for browser-level end-to-end tests

## Quick start with Docker

Requirements: Docker with Compose support.

```bash
cp .env.example .env
# Replace the example secrets and SMTP settings in .env.
docker compose up
```

Open `http://localhost:3000`. The API documentation is available at
`http://localhost:8000/docs`.

## Local development

Requirements: Node.js 22+, Python 3.10+, PostgreSQL 14+, and Redis.

Create the root environment file first:

```bash
cp .env.example .env
```

Run the backend:

```bash
cd backend
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
python -m alembic upgrade head
python -m uvicorn app.main:app --reload
```

Run the frontend in another terminal:

```bash
cd frontend
npm ci
npm run dev
```

The frontend proxies `/api` through the server-only `BACKEND_URL` setting.

## Tests and validation

Backend:

```bash
cd backend
python -m ruff check app tests migrations
python -m unittest discover -s tests -v
python -m alembic upgrade head
python -m alembic check
```

Frontend:

```bash
cd frontend
npm ci
npm run lint
npm run type-check
npm test
npm run build
```

End-to-end tests require the backend and its PostgreSQL/Redis dependencies:

```bash
cd frontend
npx playwright install chromium
npm run test:e2e
```

GitHub Actions runs backend lint/tests/migrations, frontend
lint/type-check/tests/build, Docker Compose validation, and the Playwright
journey on pushes to `main` or `dev` and on pull requests.

## Monitoring API

Authenticated API clients can use:

- `GET /api/monitors`
- `POST /api/monitors`
- `GET|PUT|DELETE /api/monitors/{monitor_id}`
- `POST /api/monitors/{monitor_id}/test`
- `POST /api/monitors/{monitor_id}/pause`
- `POST /api/monitors/{monitor_id}/resume`
- `GET /api/monitors/{monitor_id}/checks`
- `GET /api/monitors/{monitor_id}/incidents`
- `GET /api/monitors/{monitor_id}/uptime`
- `GET /api/monitors/{monitor_id}/response-time`
- `GET /api/monitors/{monitor_id}/status`
- `GET /api/incidents`
- `GET /api/alerts`
- `POST /api/alerts`
- `GET /api/alerts/deliveries`
- `POST /api/alerts/{alert_id}/test`

Interactive request and response documentation is generated by FastAPI at
`/docs`.

## Security configuration

For production:

- Set `ENVIRONMENT=production`.
- Provide unique `SECRET_KEY` and `MONITOR_ENCRYPTION_KEY` values of at least
  32 characters.
- Set `TRUSTED_ORIGINS` to the exact frontend origins.
- Set `PUBLIC_APP_URL` to the externally reachable frontend origin used in
  notification links.
- Configure the SMTP timeout, TLS/SSL, and authentication flags for your mail
  provider. Do not enable `SMTP_USE_TLS` and `SMTP_USE_SSL` together.
- Use HTTPS so Secure session cookies remain protected in transit.
- Restrict the monitoring worker's outbound network access as an additional
  defense-in-depth control.

See the root and frontend `.env.example` files for all settings.
